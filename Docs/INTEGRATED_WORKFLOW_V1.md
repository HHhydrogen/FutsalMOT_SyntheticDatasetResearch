# 三流程整体方案与终止 Gate v1

日期：2026-10-29。适用范围：本仓库仅做方案、协议和结果归档。UE生产、数据下载、训练和正式论文操作由用户交给其他对话执行；任何执行对话都必须只做被分配的一个阶段。

## 总体主线

论文建议只设一个主要科学终点：在未见真实比赛上，合成监督能否改善 MOT 身份连续性。固定检测的关联评估用于隔离关联作用，完整检测+追踪用于验证系统收益；BBox/Pose是上游诊断或次要结果，不自动并列为三条主线。长边视角、绿地面、号码属于目标域匹配和数据契约，不当论文亮点。

整个项目按三流程前进：

1. 合成数据集生成与冻结。
2. 真实数据选取、比赛切分和模型训练/评价。
3. 论文撰写和交付。

每个流程开始前有自己的冻结协议；每个流程完成后以一次正式交付结束。**通过 Gate 不自动授权或启动下一流程。**下一阶段必须由用户在另一执行对话明确启动。

## 流程一：合成数据集生成

### 进入条件

开始真实渲染前，设计协议必须确定：主研究问题和主要终点；目标应用域；schema及关键点版本；相机profile/分辨率/FPS；生成的精确seed/episode清单和每条帧数；预期camera数；每个标签产物；最大存储量；随机seed规则；生成代码/配置版本；预期发布目录；短样判据；本次最多一次修订的范围。任何一项缺失，停在设计阶段，不允许执行器自行猜测。

文献筛查在本项目最多纳入15篇核心工作，最多做两轮前向/后向引用追踪；到上限仍有空白则记为未覆盖并结束，不持续扩展检索。候选真实来源仅用于生成前确定目标域和标签兼容性；正式比赛train/dev/test身份仍在流程二锁定。UE相机限制见[源工程审计](SOURCE_ENGINE_AUDIT_V1.md)。

### 执行与发布

- 一个完整模拟比赛seed为一个不可拆分发布单元；同seed派生的所有camera、appearance和帧只能属于同一synthetic split。
- 每次发布到新版本目录。先写 `_work/<attempt>/raw`，校验后写 `_staging/<attempt>`，验收后同卷原子发布；严禁覆盖既有版本。
- 短样最多两轮：初样一轮；仅当发现可定位问题时允许一次、只修该问题的复验。第二轮仍不通过则`FAIL_STOP`，不扩成无限材质/机位探索。
- 全量只生成冻结清单中的seed、帧数和相机。达到准确数量即停止；不得因图片“看起来还可以优化”追加seed/角度/外观。
- 每个unit按[数据集契约](DATASET_CONTRACT_V1.md)逐项校验。失败产物留在attempt诊断范围，不进入发布版本。发布版本只读。

### Gate 1：数据集生成终止条件

**PASS**必须全部成立：冻结清单中所有unit正好各发布一次；根/逐unit清单、schema和代码版本绑定完整；每camera预期帧数一致；RGB、instance mask、number mask、标注和相机状态帧号一致；轨迹/ID稳定性、Pose字段、号码字段、bbox-mask对应关系和目录白名单检查全部通过；SHA256 manifest完整；实际容量未超过冻结上限；没有额外文件或缺失文件；最终版本路径与指纹已记录。

**FAIL_STOP**：最多一次针对性短样修订后仍失败；出现无法按原协议解释的数据/标注；预计容量超上限；需要修改schema/相机生成代码/seed规则/样本数。此时保存证据、列出唯一的下一决策点并结束本轮，不继续试错。修订需求必须新建协议和版本。

**流程一交付**：唯一发布根路径、dataset fingerprint、unit计数、完整性/QC汇总、所有失败或缺失、schema/配置/代码版本、相对冻结计划的差异（应为零）、Gate结果。交付后停止。

## 流程二：真实数据选取、模型训练与评价

### 真实数据选择（训练开始前第一步）

- 候选真实数据源最多初筛3个；用固定表对比许可/可访问性、整场身份、标签兼容、相机分布、比赛难度、历史使用暴露和文件完整性。
- 先审比赛真实身份与历史暴露，再按完整比赛锁train/dev/sealed test。同场片段、镜头或重编码不能跨split。旧项目已观察的12场是development；SNMOT-116/187和封存包不能用作本新方案的盲测。
- 至少指定一个主要真实来源；可指定一个外部验证来源。没有足够未观察且许可可用的比赛，则停止并报告split不可行，不得把同场新clip当新比赛。
- 普通/中等交互/强遮挡分层规则在看本轮模型结果前冻结。难度标签由图像/事件客观规则产生；总体结果仍按完整比赛统计。

### 训练顺序与公平控制

1. BBox：R-only、S-only诊断、S→R、R+S策略按冻结协议比较。报告训练真实曝光、合成曝光、总更新和资源。若预算不允许完整全因子矩阵，协议中提前指定主对照和探索臂。
2. Pose：先锁唯一关键点拓扑、坐标单位、visibility语义和可见性缺失处理；不允许将历史12点追溯命名为COCO17。Pose结果作为独立任务指标。
3. MOT关联：冻结同一detector预测/阈值/候选输入；比较原ByteTrack/预先选定强motion参考/学习关联器，Pose on/off采用同容量控制，真实和合成窗口预算显式分列。
4. 全系统：前面完成后再测检测+追踪全链路，作为系统次要结果；不能把上游AP变化归因关联器。
5. YOLO11n/s/m只比较已冻结的模型和训练臂。不要动态追加尺寸或按开发结果临时选择最好规模；每模型size均报告绝对值、延迟、吞吐、显存。

### Gate 2：模型训练与评价终止条件

训练启动前，协议必须列出：真实split manifest；数据版本；模型/预训练权重/可训练层；优化器/LR/图像尺寸/batch/updates；各臂唯一真实和合成UID/曝光预算；loss权重；增强；seed；训练终点；推理阈值；检测/跟踪评价设置；模型数量；预期运行数；资源上限；失败重试规则；主要指标、配对统计单位和区间方法。**任何数字为空时不开始训练。**

- 运行只覆盖协议登记的组合；不按分数挑checkpoint/seed、不增训、不搜索未登记阈值。
- 因硬件/作业中断的运行，允许原配置完全不变的重启一次；因指标低或负结果不允许重试。需要修数值/代码错误时，先留完整失败记录，再冻结修订版；不得悄悄接续或覆盖旧run。
- Development阶段的训练、推理和评价总量有冻结上限。达到上限或完整执行清单时停止，未完成项列为未执行，不自动扩时。
- Sealed test只在所有选择完成后由一个冻结runner运行一次。基础设施故障最多原样重跑一次；读到测试结果后禁止继续改模型/阈值。若必须修评测代码，现有test失去独立盲测地位，须重新锁未观察比赛。

**PASS**：所有预登记运行均有`completed/failed/not_executed`状态；全部主对照和预定区间结果可从固定输出复现；逐比赛绝对成绩、差值和全部seed齐全；资源/协议差异列出；test访问收据和checkpoint/代码绑定齐全；负结果完整；无未解释split泄漏。

**FAIL_STOP**：一轮原样重试后仍为基础设施失败；需要增加模型/训练预算/数据源；主评测缺关键来源；split泄漏；关键schema变更。记录后停，不由同一agent换方法继续跑。

**流程二交付**：冻结protocol、数据源与split清单、训练历史、模型权重索引、绝对结果/配对差/比赛级区间、资源统计、失败/未执行清单、test访问记录、Gate结果。交付后停止。

## 流程三：论文撰写

论文使用流程一/二的冻结结果。文献综述与大纲可以提前；正式写作阶段只引用已经锁定的结果、协议和来源。绝不把领域常见属性写成创新，也不将开发集结果写成测试集泛化；负结果、范围差异和数据许可写清楚。

### Gate 3：论文交付终止条件

- 提交一份完整稿（摘要/引言/相关工作/数据和方法/实验/结果/局限/结论/参考文献/图表）。
- 论文每个数字和主张都链接到一个冻结结果/文献记录；表格报告各方法绝对成绩、差值和区间，缩写和指标一致；方法/数据结构/协议可复现；版权许可和数据发布声明经核对。
- 最多两轮整体修订。第二轮后仍有问题，列入“待作者决策”，不开始无边界润色，不擅自改变研究问题或重启训练。

通过后提交稿件、引用核验表、主张—证据表、仍待作者决定事项并停止。投稿/公开发布属于另一明确任务。

## 全局停止规则

Gate有三种状态：`PASS`（交付并停止）、`FAIL_STOP`（有限修复后仍不通过，交付诊断并停止）、`BLOCKED`（缺来源/许可/权限/用户决策，列出最小待决项并停止）。每轮agent只能推进一个flow，不以“顺手完善”为理由跨Gate；通过或失败后都等待用户显式启动后续阶段。任何新研究问题、样本扩量、schema变化、seed搜索、test替换都产生新版本协议，不在当前任务无限延伸。

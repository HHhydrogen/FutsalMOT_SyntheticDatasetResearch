# 新实验论文主线与研究方案 v1

日期：2026-10-29。状态：提案，未冻结训练协议；不代表预期提升已成立。

## 1. 论文问题

**在比赛级隔离和训练预算可比较的条件下，程序化合成足球数据是否能改善未见真实比赛上的球员检测与追踪？** 改善来自哪些任务、训练策略和模型容量，在哪些比赛难度下稳定出现？

建议工作标题：**FutsalMOT-Synth: Controlled Synthetic Data for Cross-Domain Player Detection, Pose Estimation, and Tracking**。标题暂不把“Pose提升MOT”写进结论：过往项目结果显示合成窗口对关联有有限的开发集作用，但Pose分支没有稳定超过强motion基线；此次应重新独立验证。

## 2. 与近邻工作的定位

足球/体育追踪数据集、合成多人体时序数据、体育检测合成数据和球衣号识别已有研究（逐篇见 `../literature/`）。因此不主张“首个足球合成数据集”“首次合成足球检测”或“首次球衣号MOT”。可检验的差异组合是：

1. 以真实足球视觉任务可复现的合成时序数据作为研究资源，明确数据契约、标注完整性和质量审计。
2. 通过固定真实比赛测试和预算对照，拆分合成预训练、联合训练与真实微调的边际作用。
3. 逐层测量检测、Pose和身份关联，避免把一个阶段的改进归因给另一个阶段。
4. 按完整比赛和预先定义的场景难度报告泛化、负迁移及不确定性。
5. 比较YOLO11多个容量等级，检验合成监督收益对模型规模是否稳健。

根据原项目目标，建议以MOT身份连续性作为论文唯一主要终点；固定检测的关联评估用于隔离关联贡献，完整检测+追踪作为系统级验证。BBox和Pose是上游诊断/次要结果，不与MOT并列为三个同等主线。若希望改成多任务数据集论文，需在实验前重写主问题和主要终点。长边机位、绿色地面、号码以及bbox/Pose/ID标注完整性属于目标域匹配和数据质量要求，本身不作为论文创新点。候选论文贡献只有在数据与实验完成后确认： (a) 真实足球任务可用的同步时序监督资源及可复核质量审计；(b) 受控跨域训练评估；(c) 合成训练策略、任务类型和模型容量的实证规律。UE工具链、分辨率或素材属性本身不是学术贡献。

## 3. 预注册假设与可证伪条件

- H1：新版本合成数据相对同初始化的真实训练基线，在未见比赛的预先指定主要任务指标上有可复现增益；视角、地面和号码改动只作为域匹配/标注质量控制。
- H2：合成预训练后真实微调可能优于纯真实训练；它与混合训练是不同策略，必须分别比较，不能只报更优的一种。
- H3：同一检测框/固定检测输入下，关联器若使用Pose监督，其身份关联收益需要超过强motion对照；否则只报告检测或Pose结果，不能归因MOT提升。
- H4：n/s/m不同容量会改变迁移收益；若跨容量不一致，结论限定模型规模。
- H5：一般/中等/困难场景的收益可能不同。总体集表现和各层结果均报告，不能以困难集下降掩盖总体，也不能靠只测容易场景抬分。

不以单一AP或单场HOTA通过作为“合成数据有效”的充分条件。每个假设均预先给主要指标、实验臂、样本单位与区间估计；门槛数值在读入新测试前由开发数据和功效/资源计划冻结。

## 4. 阶段路线与准入

### A. 文献与研究设计门（当前阶段）
核对研究近邻、论文中心任务、数据契约和训练策略；静态盘点UE相机、green-floor、appearance seed与号码原型边界。先从候选真实数据了解目标应用域和标签格式，但正式train/dev/test身份留到第二阶段锁定。完成候选来源/许可/历史曝光清单和生成准入协议。

### B. 合成数据集生成与冻结
同一轨迹和角色seed，先用现有camera task profile / UE camera mapping做长边全场视角短样，角落视角作为对照。当前运行时可选C1–C5和固定左半场P01；新加长边偏移或动态pan/zoom前，需先核对并扩展运行时支持，不能只写配置或假定ratio会生效。绿色基线、小幅色调/明暗变化及号码作为目标域/契约要求纳入短样。读回实际Camera transform、材质参数、号码纹理/位置、actor-ID至标签映射、逐帧bbox/mask/Pose。短样通过后再冻结版本并完整生成。号码不得遮挡/伪造身体Pose；号码字段的可见性、遮挡与身份映射要定义清楚。

### C. 生成集质量验收与版本冻结
在训练前固定统计：相机俯仰/方位/视场角/焦距和场上覆盖；玩家像素高度/框面积分布；色彩/照度；号码可读率；遮挡/截断层级；关键点支持和可见性语义；ID连续性、轨迹断裂、重复帧、空标注、mask-bbox一致性。按序列统计，样本不是独立帧。与真实train/dev仅作域描述，不窥视封存test。

### D. 真实数据选取、比赛级split锁定（模型训练阶段第一步）
完成候选真实集的来源/许可/标签兼容核对，排除已观察比赛作为盲测；按完整比赛锁定train/dev/sealed test，核实同场剪辑和转码。常规、交互、强遮挡作为分层/事件panel。难度标签由训练前规则构成，不根据模型错误或分数挑帧。此门未通过不得开始正式模型训练。

### E. 模型训练与逐层验证
1. BBox：真实only、合成only、合成预训练→真实微调、真实+合成联合。先检验domain/label质量，再扩模型尺寸。
2. Pose：先冻结唯一关键点schema及可见性规则；与检测分开报告。号码字段不等于Pose点。标准17点COCO或自定义schema二选一并全程固定，不能把历史12点追溯改名。
3. MOT：先固定detector预测和候选集，比较ByteTrack/强motion/学习关联器；隔离Pose输入消融。之后才做全系统联合展示，不能把检测改善误归因关联。
4. 每阶段通过开发准入后才开始下阶段；正式test仅一次冻结评价，测试结果不用于修改模型。

## 5. 训练策略主比较

对BBox和Pose各设独立任务矩阵：

- R-only：通用预训练初始化后，仅用真实train训练/微调。
- S-only：同一初始化，仅用新合成数据训练，测sim-to-real直接迁移。
- S→R：先在合成集预训练，再在相同真实train微调；冻结S阶段与R阶段预算。
- R+S：合成与真实混合训练；控制每轮真实样本数/真实曝光，并记录S:R采样比例。

S→R与R-only总更新次数不相等时，需同时提供两种公平对照：固定真实数据曝光，以及固定总优化更新/计算预算。不要把“S先多训一段”本身当合成的数据收益。报告训练吞吐、显存和总时长；每个臂使用同一初始化和预先登记seed。数据量/训练预算选定后写入绝对数值协议，不在本提案伪造尚未跑过的最佳预算。

MOT主分析固定检测和Pose提取，训练关联器使用相同真实窗口预算，额外合成窗口单列曝光数；另设不含Pose的同容量motion控制。整系统检测变化仅作为次要端到端实验。

## 6. 模型尺寸与评价

建议第一轮覆盖YOLO11n/s/m的detect规格；Pose任务同步使用n/s/m-pose（若官方权重/代码实际可用且版本相同），不得用detect AP横比Pose AP。模型输入、训练图像数、更新数和增强策略相同；同时报告参数量、延迟/吞吐、显存，且用多个seed估计波动。若资源只允许先测n/s，则把m列为后续，不把n结果外推到大模型。

BBox：AP50、AP50:95、召回/精确率、按人物像素尺寸和场景难度分层。Pose：OKS AP/AR及每点误差、可见性覆盖；Pose模型单独报告。MOT：HOTA及DetA/AssA分解、IDF1、MOTA、IDSW/fragmentation；同一评价程序、检测输入和输出策略。

“按比赛评价”是足球MOT的自然单元：一场比赛内部连续帧高度相关，片段/帧不是独立实验样本。每场先独立算分，再列总体micro/pooled（按指标定义）与比赛等权macro平均，并以比赛为单位做配对差值区间；同时报告每场分数和预定难度panel。只报告单场不够，跨场汇总和区间也要有。SoccerNet等基准按序列/比赛拆分测试；不同检测器、类别定义、数据和协议的公开分数不能直接与本项目横向排位。

## 7. 判定和论文表述

主要因果问题先比较S→R vs R-only，以及R+S vs R-only（同测试比赛、同模型、同真实曝光/明示总预算）。报告绝对值、配对差值、比赛级95%区间和全部seed；若区间跨零就报告不确定，避免“显著提升/等效”断言。无论结果正负都保留。

测试集必须在训练/调参完成后一次性运行。若需持续开发，建立未见train/dev比赛，不重复读取最终test。预先定义的合成数据版本、模型checkpoint终点、推理门槛和评价代码全部哈希/绑定到冻结协议。

## 8. 项目工作流与当前未决项

项目总流程可按“合成数据集生成 → 真实数据选取与模型训练 → 论文撰写”推进，但前置有一项轻量设计门：在生成前先确定研究主问题、目标应用域、候选真实来源和数据契约；否则生成出的视角/分辨率/schema可能无法回答后续问题。第二阶段开始时先锁定真实train/dev/test，再训练；最终测试保持封存。论文结构、相关工作和方法草稿可与前两阶段并行准备，结果、结论和讨论只能基于协议冻结后的完整实验。

当前未决项

- 主要终点建议为MOT身份连续性；BBox/Pose定位为辅助分析。需要在第一份冻结协议前确认，避免三个任务同时成为主线。
- 新研究仓库具体GitHub远端、论文venue/投稿期刊、经费/商用许可尚未设置。
- 新真实比赛列表需从源、许可证和历史暴露清点后选；不沿用封存test或把旧开发集伪装成新test。
- UE号码功能仍需查现有WIP并决定可读纹理实现及label schema；绿地材质新版本需真实读回；长边相机需真实CineCamera输出短样。
- 模型训练绝对预算、difficulty阈值、最小独立比赛数、统计把握度尚未冻结；正式训练前单独登记，不根据test分数挑选。
